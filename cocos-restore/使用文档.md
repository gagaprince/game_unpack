# wxrestore 使用文档

把**微信小游戏（Cocos Creator 3.x 构建）的解包目录**还原成可用同版本
Cocos Creator 打开的工程。当前在 **Cocos Creator 3.8.8** 构建产物上验证。

- 仓库目录：`/Users/zidong.wang/aiwork/game_unpack/cocos-restore/`
- 入口：`restore.py`（还原）、`verify.py`（无头校验）
- 档位：**B 档** = 全部资产（图/音频/粒子/动画/场景/全部 Prefab）
  + 自定义组件的**空壳脚本**（保留原 UUID 与类 id、属性声明，方法体为空）

---

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| 系统 | macOS（工具用编辑器安装目录识别内置资源；其他平台见「跨平台」一节） |
| Python | 3.9+（命令行 `python3`） |
| Pillow | **可选**。仅「图集裁帧」需要：`python3 -m pip install pillow`；不装也能完整还原独立图片（直接拷贝原始 PNG/JPG），只有仅存在于图集、需要裁剪的帧会失败并在报告 `failed` 中标注 `atlas-crop-needs-Pillow` |
| Cocos Creator | 需安装 **3.8.8**，用于打开还原工程与建立内置资源黑名单 |

**除 Python 标准库外无其他强制第三方依赖。** 不依赖 Node、不需要联网，不修改原始解包目录。
不装 Pillow 时本案例实测：314 张独立图正常还原、`missing_native=0`，仅 14 帧图集裁剪失败（报告中明确标注原因）。

## 2. 输入：解包目录长什么样

输入是**已经解包完的微信小游戏目录**（`.wxapkg` 解包之后的产物），典型结构：

```
某游戏_unpacked/
├── game.js / app-config.json      # 小游戏入口与配置
├── src/
│   └── settings.json              # 工程设置（分辨率、物理分组、启动场景等）
├── assets/                        # 主包与内置 bundle
│   ├── internal/                  # 引擎内置 bundle（会被识别并跳过重复资产）
│   ├── main/
│   └── start-scene/
│       ├── config.json            # bundle 索引
│       ├── index.js / index.json
│       ├── import/                # 序列化资产（packed json / CCON）
│       └── native/                # 图片、音频等二进制
└── subpackages/                   # 分包 bundle（每个子目录结构同 assets 下的 bundle）
    ├── game/
    ├── fruits/
    └── ...
```

工具靠每个 bundle 下的 `config.json` + `import/` + `native/` 识别资源，
不依赖固定目录名，会自动扫描主包与分包。

> **分包缺失**：`game.json`/配置里声明、但解包目录中不存在的分包无法还原，
> 会列入报告的 `missing_bundles`，引用这些分包资源的地方会悬空。
> 若需要完整还原，请先把对应分包 wxapkg 也解包到同一目录树下。

## 3. 快速开始

```bash
cd /Users/zidong.wang/aiwork/game_unpack/cocos-restore

# 1) 还原
python3 restore.py \
  /路径/某游戏_unpacked \
  /路径/输出工程目录 \
  --name my-game

# 2) 无头校验（强烈建议，秒级，不用开编辑器）
python3 verify.py /路径/输出工程目录 --src /路径/某游戏_unpacked
```

实例（本次案例）：

```bash
python3 restore.py \
  /Users/zidong.wang/aiwork/game_unpack/package/wxf41b76649658b9e3_unpacked \
  /Users/zidong.wang/aiwork/game_unpack/restored_wxf41_v3 \
  --name restored_wxf41_v3
```

控制台会依次打印 5 个阶段：扫描 bundle → 建全局索引 → 生成工程骨架 →
写资产 → 生成脚本壳，最后给出数量统计和报告路径。

## 4. 命令参数

### 4.1 `restore.py`

```
python3 restore.py <src> <out> [--name 名称] [--editor CocosCreator.app路径]
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `src` | 是 | 解包目录（见第 2 节） |
| `out` | 是 | 输出工程目录；**不存在会自动创建，已存在会向里写文件（建议用空目录）** |
| `--name` | 否 | 工程名，写入 `package.json`，默认 `restored-game` |
| `--editor` | 否 | `CocosCreator.app` 路径；默认取 `/Applications/Cocos/Creator/` 下最新版本 |

`--editor` 的用途是扫描编辑器自带资源（默认 UI 图、内置粒子、内置
材质/effect）的 UUID，避免把构建包里夹带的同名内置资源重复落盘导致
UUID 冲突。非标准安装位置时需要显式指定。

### 4.2 `verify.py`

```
python3 verify.py <project> [--src 解包目录]
```

| 参数 | 说明 |
| --- | --- |
| `project` | 还原出的工程目录 |
| `--src` | 原始解包目录；提供后可把「策略性不还原」的悬空引用（如材质）标成 `degraded-ref` 而非硬错误 |

退出码：无硬错误返回 `0`，有硬错误返回非 `0`（可用于批量脚本）。

## 5. 输出目录结构

```
输出工程/
├── assets/                    # 还原的全部资产（按原 bundle/路径组织）
│   ├── scripts/restored/      # B 档：自定义组件空壳 .ts + .meta
│   ├── <bundle名>/...         # 图片/音频/prefab/场景/动画等，尽量保留原相对路径
│   └── **/*.meta              # 每个资产/目录的 meta（UUID 与原工程一致）
├── settings/  profiles/       # 从 empty-2d 模板复制的工程设置
├── package.json  tsconfig.json
└── restore-report.json        # 还原报告（见第 7 节）
```

资源命名规则：构建产物里多数资源只剩 UUID，工具按
`<bundle>/<类型目录>/<短uuid>.<ext>` 落盘；配置里带原始路径的资源
（如 `db://assets/res/scene/gameNew.scene`）会保留可读路径与文件名。

## 6. 在 Cocos Creator 中打开与验收

1. 用 **Cocos Creator 3.8.8** 选择「打开已有项目」，指向输出目录。
2. 首次打开会自动导入资源、编译脚本，资源较多时请等待右下角导入进度结束。
3. 在 **Assets** 面板找到场景（本案例为 `assets/res/scene/gameNew.scene`），
   双击打开；逐个打开 Prefab 目检。
4. 打开 **Console** 面板，正常情况下应无红色报错。

> 不要同时用另一个 Cocos 实例打开同一工程；如需在第二实例打开而其要求
> 重新登录，可改用「把还原工程的 `assets` 拷进一个已登录工程的子目录」
> 的方式做导入验证（UUID 引用与路径无关）。

**验收要点**

- 场景节点树、组件、Sprite 图片、UI 布局正常显示；
- 自定义组件在 Inspector 中是真实脚本组件（不是 `MissingScript`）；
- 控制台无 `A Class already exists with the same __cid__`、无
  `uuid is already pointing to another asset`。

## 7. 还原报告 `restore-report.json`

| 字段 | 含义 |
| --- | --- |
| `bundles_on_disk` | 实际在解包目录中找到的 bundle |
| `declared_subpackages` / `missing_bundles` | 声明的分包 / 目录中缺失的分包 |
| `counts.written_files` | 写出文件总数 |
| `counts.cropped_from_atlas` | 仅存在于图集、被裁剪出来的帧数 |
| `counts.skipped` / `skipped_assets` | 跳过的资产（含内置资源、材质/effect/图集资产等，附类型与原因） |
| `counts.skipped_builtin` | 其中因「引擎内置资源」而跳过的数量 |
| `counts.missing_native` | 有序列化数据但缺二进制（图/音频）的资产 |
| `counts.no_pil_passthrough` | 未安装 Pillow 时，按原始字节直接拷贝的独立图片数（尺寸从 PNG/JPEG 文件头解析） |
| `counts.failed` / `failed` | 处理异常的资产（理想为 0；未装 Pillow 时图集帧会是 `atlas-crop-needs-Pillow`） |
| `counts.scripts` / `scripts` | 生成的脚本壳清单：原类 id、文件、UUID、属性字段 |
| `counts.legacy_scripts` | 2.x 迁移来的虚线 id 脚本（已用 `setClassAlias` 兼容） |
| `launch_scene` | 从 `src/settings.json` 读出的启动场景 |
| `degraded_notes` | 各降级项的文字说明 |

## 8. `verify.py` 结果怎么看

关键字段：

- `ok: true` —— 无硬错误（`degraded-ref` 不算硬错误）。
- `unresolved_uuid_refs` —— 指向「源包里根本不存在」资产的引用数，应为 0。
- `bad_id_refs` —— 序列化数组内 `__id__` 越界数，应为 0。
- `missing_script_shells` —— 场景/Prefab 用到但没生成壳的脚本，应为空。
- `problems` 里的 `degraded-ref` —— 指向**存在但按 B 档策略不重建**的资产
  （本案例是 2 个自定义材质），打开时由引擎回退内置材质，属预期。

## 9. 已知限制（都有源码/编辑器实证）

| 项 | 现象 | 原因 |
| --- | --- | --- |
| 自定义材质 / Effect | 相关 Sprite 回退内置材质 | 构建包只含编译后的 EffectAsset 描述与 GLSL，不含 `.effect` 源 |
| SpriteAtlas / AutoAtlas | 不还原图集资产本体 | 帧已按独立散图导出且 UUID 不变，引用不断 |
| 嵌套 Prefab | 含「prefab 套 prefab」的资源打开时可能报 `getOutMostPrefabInstanceInfo ... root node has loop` 告警 | 构建产物缺编辑器侧 `mountedChildren` 等挂载描述；节点/组件/资源仍完整，可查看、可运行时实例化 |
| 脚本方法体 | 组件属性在、逻辑不执行 | 编译产物不含 TS 源码，只能生成属性空壳 |
| 缺失分包 | 引用悬空 | 对应 wxapkg 未解包 |
| 内置资源 | 不在 `assets` 里出现 | UUID 直接解析到编辑器自带副本，避免冲突 |

工程级设置（设计分辨率、适配策略、2D 物理重力/分组/碰撞矩阵、启动场景）
会从 `src/settings.json` 恢复；其中物理分组矩阵的写入格式建议首次打开后
在「项目设置」里再核对一次。

## 10. 常见问题

- **打开后自定义脚本显示 `MissingScript`**：先确认脚本已编译完成
  （Console 无编译错误、右下角导入结束），再重新打开一次场景；
  2.x 虚线 id 的脚本由生成代码里的 `js.setClassAlias(...)` 注册，
  若仍缺失，把该组件的 `Class ID` 与 `assets/scripts/restored/`
  下 `.ts` 的 `@ccclass('...')` 比对是否一致。
- **`uuid is already pointing to another asset`**：通常是输出被拷进了
  已含同 UUID 资产的工程，或用了不带内置黑名单的旧版工具；用最新工具
  重新生成到空目录即可。
- **图片缺图（`missing_native>0`）**：对应纹理的 native 文件在
  `native/` 里缺失或位于未解包的分包。
- **图集里的小图**：工具会按 SpriteFrame 的 rect/旋转/offset 从图集裁出
  独立 PNG（计入 `cropped_from_atlas`）；需要 Pillow。
- **重跑前**：若输出工程正在编辑器里打开，先关闭该工程或编辑器，
  再重新执行 `restore.py`，避免文件占用。

## 11. 用新案例回归时的标准流程

```bash
# 1. 还原到全新目录
python3 restore.py <新解包目录> <新输出目录> --name <名字>
# 2. 无头校验，先看 ok 与 failed/missing_native/missing_bundles
python3 verify.py <新输出目录> --src <新解包目录>
# 3. 用 3.8.8 打开，按第 6 节目检场景与若干 Prefab
```

判断一个新案例是否达标，建议收集：
`restore-report.json`（尤其 `failed`、`missing_native`、`missing_bundles`、
`degraded_notes`）、`verify.py` 完整 JSON、打开后 Console 红色报错截图。
把这些反馈给工具维护者即可定位通用性问题。

## 12. 模块概览（供二次开发）

| 文件 | 职责 |
| --- | --- |
| `wxrestore/packed.py` | packed JSON v1 解包 |
| `wxrestore/msgpack_codec.py` | CCON msgpack 编解码 |
| `wxrestore/ccon.py` | CCON 二进制解析 + RealCurve 解码 + 转编辑器文档 |
| `wxrestore/uuid.py` | UUID 压缩/解压、脚本类型 id 判定 |
| `wxrestore/builtins.py` | 编辑器内置资源 UUID 黑名单 |
| `wxrestore/bundle.py` | bundle（config/index/import/native）读取 |
| `wxrestore/indexer.py` | 跨 bundle 全局资产索引 |
| `wxrestore/editorize.py` | 运行时对象图 → 编辑器扁平序列化数组（场景/Prefab/嵌套 Prefab） |
| `wxrestore/images.py` | 图集裁帧 |
| `wxrestore/metas.py` | 各类资产/目录/脚本 meta 生成 |
| `wxrestore/scripts_shell.py` | B 档组件空壳脚本（含 legacy id 别名注册） |
| `wxrestore/project.py` | 工程骨架与分辨率/物理配置 |
| `wxrestore/writer.py` | 资产写入编排与脚本字段扫描 |
| `verify.py` | 无头完整性校验 |
| `legacy/`、`work/` | 早期案例分析/调试脚本（存档，勿被正式工具引用） |
