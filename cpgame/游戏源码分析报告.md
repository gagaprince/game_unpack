## 1. 游戏基本玩法（每条均附源码依据）

**结论：这是一款「物理掉落 + 相同物品合成消除 + 关卡推进」的休闲游戏（合成大西瓜类玩法），带 6 套主题皮肤、道具、城市图鉴与广告变现。** 不是猜测，证据链如下。

### 1.1 核心机制：2D 物理场内掉落水果，相同水果碰撞消除

- 物理场：`settings.json` 开启 Box2D 2D 物理（重力 (0,-10)、5 个碰撞分组 fruit/wall/obst/clickFruit/guardrail、碰撞矩阵）；`cocos-js/assets/box2d.release.wasm` 在包内。
- 水果/蔬菜本身是刚体：`fruits` bundle 的 33 个 prefab（fruit1–33）每个都是 `cc.Sprite + cc.RigidBody2D + cc.PolygonCollider2D`（见附件树，如 fruit1=西瓜）；`vegetable` 的 28 个同理（Polygon 或 CircleCollider2D）。
- 关卡容器 `prefab/game/GbzLvCommon`（game 包）内含：四周十余个刚体碰撞墙（`left/right/dropLeft/dropRight/floor/top/bottom/canCheck`，均为 RigidBody2D+BoxCollider2D）、多边形地面 `wall`（RigidBody2D+PolygonCollider2D）、两个篮子 `basket01/02`、水果挂点 `fruits`、障碍挂点 `obstaclesRoot/stakeRoot`、特效挂点 `effsRoot`。
- 消除规则的**直接文本证据**：同 prefab 内教学提示节点 `leaderTip`：
  - roundone 三句 Label：**「2个」「相同」「的水果会消除」**
  - roundtwo 四句 Label：**「2个」「相同」「的磁铁会消除」「一组水果」**（默认 INACTIVE）
- 音效原名佐证：`audios/相同水果碰撞`、`audios/xiaochu_1..5`（消除音 5 个）、`audios/水果消除bgm`、`audios/水果消除关卡bgm`、`audios/水果消失`、`audios/水果落地`、`audios/装不下啦`。
- 失败条件：节点 `full` 内 Label **「装不下啦」**；失败弹层 `GbzLoseFullLayer`（secondary 包），文案「本关已挑战 N 次」。

## 4. 问题 3：资源原始名称 ↔ 当前路径关系

全量对照见 `resource_inventory.csv`（1451 行，列：bundle / uuid 序号 / 原始路径 / cc 类型 / 完整 uuid / 短 uuid / 所在 pack / import 磁盘路径 / native 磁盘路径）。

**命名/存放规则（从 config.json 与磁盘实测归纳）：**

1. 每个 bundle 一份 `config.json`（`assets/start-scene/config.json`、`subpackages/<bundle>/config.json`），其中 `paths` 给出「编辑器原始路径」，`uuids` 给出每资源 uuid，`packs` 给出多资源合并包。
2. 序列化 JSON（prefab/scene/材质等）：`subpackages/<bundle>/import/<uuid前2位>/<完整uuid>.json`；多个资源被合并进 pack 文件时，文件名为短 uuid，如 `subpackages/game/import/0d/0d785ed53….json`，pack 内 section 顺序 = `config.packs` 给出的 index 列表顺序（GbzLvCommon 就在该 pack 中）。
3. 原生资源（图片/音频/粒子/plist）：`subpackages/<bundle>/native/<uuid前2位>/<完整uuid>.<ext>`，扩展名保留原类型：`.png/.jpg/.mp3/.plist`；音频原始文件名只保留在 config 的 paths 里（例如 `audios/相同水果碰撞` → `…/native/ff/ff8aabf4-8f38-41de-ae64-48489383b600.mp3`）。
4. 同一图片资源拆成 3 个子资源：ImageAsset（裸 uuid）、Texture2D（`@6c48a`）、SpriteFrame（`@f9941`）；CSV 中这些行的原始路径带 `/texture`、`/spriteFrame` 后缀。
5. **414 行 `original_path` 为空**：它们是引擎自动生成的子资源或 SpriteAtlas（AutoAtlas）合图内子图，编辑器中没有独立路径；用 uuid/类型仍可唯一定位，引用它们的 prefab 行在附件树里会显示 `bundle:(subasset)`。
6. start-scene 包图片没有工程路径（paths 只登记了场景/物理材质/管线 3 项），其用途靠场景节点引用 + 图片目视确认（见 2.1）。
7. 根目录另有 `background.jpg`（750×1800，与启动 bg 同尺寸，微信启动背景用途，settings 的 splashScreen 另用 base64 内联图）。

## 6. 无法确认事项（按要求显式标注）

1. **四个声明但缺失的子包内容**：`animals`（动物）、`candies`（糖果）、`seaAnimals`（海洋动物）、`sweets`（甜品）在 `app-config.json` 与 `src/settings.json` 中均有声明，但解包目录 `subpackages/` 下不存在。只能从 `game.js` 字符串确认这 4 套主题**存在**及其中文物品名，**其 prefab/图片/音频等具体资源无法确认**（原因：解包产物未包含这些子包，可能被裁剪/按需网络下载）。
2. **加载 Spine 的 SkeletonData 资源**：场景 `jiazai` 节点的 sp.Skeleton 未序列化 `_skeletonData`，全工程无 sp.SkeletonData 资源、无 .skel/.atlas 文件；无法确认其骨骼数据来自哪里（代码有 `loadResSkeletonData` 方法名，疑运行时远程加载，但无路径字符串可证）。
3. **混淆业务脚本的类名/方法级逻辑**：`game.js` 整体混淆，用户字符串被倒序切块存入索引表，**字符串无法映射回具体函数**。因此自定义脚本的「类名」、音效/动画的精确触发代码行、关卡数值（除明文段位配置外）、`vegetable24` 对应蔬菜（prefab 中 spriteFrame=null）等，无法从静态产物确认；本报告对脚本职责只给「节点+字段+模块名」级推断并已注明。
4. **第 8 个闪电动画关键帧为 null**：`resUI/lightning/anim` 第 8 帧值在资源中就是 null，其播放效果无法从静态文件确认。
5. **插件 `assets/md5/crypto-md5.js`**：`settings.json` 声明引用但解包目录内未找到该文件；用途（MD5 签名）无法在产物内核实。
6. **HUAWEI/New Sprite 与草莓立绘 1576d2539.png 的绑定**：该草莓吉祥物图（58×149）存在于 start-scene 包，但场景里 New Sprite 的 `_spriteFrame` 序列化为空、且没有出现在场景 pack 的依赖 uuid 表中；静态文件无法确认它是否/如何被挂到该节点（可能运行时设置）。
7. **AutoAtlas 内子图的独立原始名**：CSV 中 414 条空路径行（SpriteAtlas 内子图/自动子资源）在编辑器中无独立路径，只能定位到所属图集，无法给出每张子图的工程内路径。
8. **开放数据域内部逻辑**：`subContext.js`（131KB）+ `openDataContext/render/`（paiming.png、avatar.png、frame.png、1.png、2.png、0.png、frameMe.png）证明存在微信好友排行榜开放域绘制；本次未逐行分析其内部逻辑（与主玩法问题无直接关系，如需可另出报告）。
9. 1451 行映射表中，start-scene 包有 7 个 logo/小图的资源条目通过 pack 内跨段引用使用，CSV 中 pack 归属以 config.packs 为准；如个别行 import 路径为空，表示该 uuid 被打进了同包某个 pack 文件（`in_pack` 列给出了 pack 短 uuid）。
