## 1. 游戏概述（复刻目标）

竖屏 2D 物理解除/合成消除休闲闯关游戏：

- 关卡开始时**顶部预先摆放一批水果**（种类与布局由关卡配置决定）；玩家**点击其中任意一个**，该水果随即解除支撑、喷射/下落进下方箱体（漏斗）。
- 水果在箱体中受物理驱动滚动堆叠；**两个相同水果碰撞即消除**（音效 `相同水果碰撞`、`xiaochu_1~5`），伴随连击 `streak`、星星、爆炸、飘字等特效与音效。
- 水果堆过箱口警戒线（装满）则失败（音效 `装不下啦`）；关卡内水果全部消除/达成关卡目标则胜利。
- ⚠️ 顶部小车是**装饰性动画层**（`GbzCarMoveLayer`：小车沿道路巡航 + 汽车鸣笛环境音），**不参与投放**。
- 关卡中有障碍物（冰块、木桩、黑箱、云雾、关节机关）与坑位（可解锁的槽位）。
- 道具：锤子、打乱、冻结雪花、向左/向下/向右推移、闪电直线消除、磁铁吸附、特殊消除。
- 元系统：关卡进度、复活、6 段位排行榜、24 格水果图鉴、约 16 套主题皮肤、新手引导、设置。
- 平台：微信小游戏（分包、开放数据域排行榜、广告/分享/订阅）。

设计分辨率 **750 × 1334 竖屏**，`exactFit` + Widget 全面屏适配。

## 2. 总体策略

1. **MVP 优先、垂直切片**：先打通「主界面 → 点选水果下落 → 物理堆叠消除 → 胜负 → 下一关」最小闭环，再逐层加障碍/道具/元系统。
2. **平台后置、接口隔离**：玩法代码不直接调 `wx.*`，统一走 `PlatformAdapter` 接口；编辑器/浏览器用 mock 实现，微信能力在 M5 接入。
3. **配置数据驱动**：关卡、合成链、物理参数、段位、主题全部为 JSON 配置（原游戏 `rangkingConfig/carmove/guang` 为加密 cconb 无法读取，自行设计）。
4. **素材策略（待确认）**：开发期建议把解包 PNG/MP3 作为**临时占位**拷入工程（仅供调布局/手感，不进入发布包），上线前全部替换为原创或授权素材。
5. **单场景架构**：对齐原作——一个主场景，所有界面为 Prefab 动态加载（Layer 模式）。
6. **物理手感对标**：水果半径/密度/弹性、重力等参数尽量从解包预制体序列化数据中读取（非加密部分），作为自研参数表的初值。

## 5. 代码架构（映射现有目录骨架）

```
assets/scripts/
├── core/        # GameApp、EventBus、LayerManager、ResLoader、Pool、Constants
├── game/        # CarController、FruitEntity、MergeSystem、ContactManager、
│                #   LevelController、Obstacle*、Hole*、Prop*、ComboTracker、EffectPlayer
├── ui/          # HomeLayer、GameHud、WinLayer、LoseLayer、ReviveLayer、
│                #   SettingLayer、RankLayer、FruitBookLayer、ThemeLayer、GuideLayer …
├── system/      # AudioManager、SaveManager、Vibrator、PlatformAdapter(+wx/mock)、
│                #   ThemeManager、LevelManager
├── data/        # levels.json、fruits.json（进化链+物理参数）、ranks.json、themes.json
└── utils/       # 数学/缓动/调试工具
assets/res/{texture,atlas,prefab,audio,anim,config}
assets/scene/   # 唯一场景 main.scene
```

关键设计：

- `FruitEntity`：只持有刚体/碰撞器/等级 id；合成规则在 `MergeSystem`，表现（图/特效）走配置与对象池。
- 碰撞合成用 Box2D `BeginContact` + 当帧队列处理，避免回调内销毁刚体导致崩溃；同帧多对合成按队列解算。
- 失败判定：周期性箱顶区域检测 + 静止超时，而不是单帧压线即判负。
- 平台差异全部收敛到 `PlatformAdapter`（`mock` / `wx` 两个实现）。
